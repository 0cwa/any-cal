# LAN HTTPS/reverse-proxy hardening receipt

Date: 2026-09-20

## Scope and isolation

The `lan-https-reverse-proxy-hardening` unit was exercised against the actual
`any-cal-app` listener using only synthetic credentials. The probe ran in a
fresh no-network `python:3.11-slim` microsandbox with the workspace mounted
read-only. The app used a temporary `HOME`; no Anytype endpoint, account,
credential store, personal Flatpak, device, or external network was used.

The disposable VM, TLS certificate/key, temporary homes, app processes, proxy,
and generated bytecode were removed or independently stopped after the run.
The probe script is [lan_https_proxy_probe.py](../../scripts/lan_https_proxy_probe.py).

## Evidence

The final VM run emitted only the following redacted structural result:

```text
config_missing_auth_fails_closed: true
config_nonloopback_fails_closed: true
direct: no_auth=401 wrong_auth=401 health_auth=200 local_health=200
        local_dav_denied=401 global_dav=405 other_space=404
untrusted_origin_relative: true
tls: health=200 discovery_status=302 discovery_location_expected=true
      keepalive_second_health=200 unknown_ca_rejected=true
      wrong_hostname_rejected=true plaintext_downgrade_rejected=true
      duplicate_length_400=true malformed_response_redacted=true
rate_limit_statuses: [200, 200, 429]
stderr_secret_free: true
```

Interpretation:

- Missing authentication and a non-loopback proxy backend both fail closed.
- The configured bearer credential authorizes the listener; missing/wrong
  credentials do not. The separate local health credential cannot authorize a
  DAV resource. The `405` result for the authenticated contacts collection is
  the expected method-not-allowed response for `GET` on that collection.
- A request-controlled space path cannot escape the configured fixed-space
  scope (`404`). Invalid host forwarding produces a relative discovery link,
  not an attacker-controlled origin.
- A trusted ephemeral certificate succeeds through the TLS proxy, including
  discovery and a second request on the same keep-alive connection.
- Unknown CA, wrong hostname, and plaintext downgrade attempts fail closed.
- Duplicate `Content-Length` framing returns `400`; the synthetic credential is
  absent from the response. The bounded rate limiter returns `429` after two
  accepted requests in the synthetic two-request window.

## Source changes

No product-code defect was reproduced, so no application source change was
needed. The existing trusted-proxy, authentication, fixed-scope, framing,
rate-limit, and redaction behavior passed the live listener probe. The only
added artifact is the reusable disposable probe script and this receipt.

The host-restricted `cargo test -p any-cal-app --offline` run still reports the
three previously known listener tests as `Operation not permitted` while
binding sockets. The no-network VM run above is the authoritative socket
evidence for this unit; the other five app framing tests passed in the host
run.
